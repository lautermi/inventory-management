Data Flow

Request Lifecycle

1
User changes a filter
FilterBar updates useFilters singleton state — e.g. selectedLocation = "Tokyo"
2
Reactive watcher triggers
Each view watch()es filter refs and calls loadData() when any change
3
API call with query params
api.getInventory({ warehouse: "Tokyo" }) → GET /api/inventory?warehouse=Tokyo
4
Backend filters in-memory data
apply_filters() and filter_by_month() run sequentially on loaded JSON arrays
5
Pydantic validates response
Each object serialized through its model, returning typed JSON
6
Computed properties re-derive
Vue reactivity propagates — computed props like filteredItems, categoryData, orderHealthMetrics recalculate automatically

Filter System

All 4 global filters flow from a shared composable singleton to each API endpoint as query parameters.

selectedPeriod
all · YYYY-MM · Q#-YYYY
→
?month=Q1-2025
selectedLocation
all · San Francisco · London · Tokyo
→
?warehouse=Tokyo
selectedCategory
all · Circuit Boards · Sensors…
→
?category=sensors
selectedStatus
all · Delivered · Shipped…
→
?status=delivered
Backend Filter Logic
apply_filters(items, warehouse, category, status)
  → exact match on warehouse
  → case-insensitive on category, status

filter_by_month(items, month)
  → Q1-2025 expands to ['2025-01','2025-02','2025-03']
  → matches substring in order_date

Composables (Shared State)

useFilters.js Singleton · global
Holds the 4 filter refs, provides getCurrentFilters() and resetFilters(). Shared across all views — changing a filter anywhere updates all pages.
useI18n.js Locale + currency
EN/JA locale switching, translation lookup with fallback, currency formatting (USD ↔ JPY at ×150 rate). Persisted to localStorage.
useAuth.js Mock user
Hardcoded user profile (John Doe / 田中 太郎), mock task list, profile metadata. Tasks merged with API tasks in App.vue.

Key Computed Metrics

Dashboard Metrics (Frontend)

On-Time Delivery Rate
(orders where actual_delivery ≤ expected_delivery) / total_delivered × 100
Avg Fulfillment Days
mean( (actual_delivery − order_date) / ms_per_day )
Demand Change %
(forecasted − current) / current × 100
Inventory Value (by category)
sum( quantity_on_hand × unit_cost ) per category

Dashboard Summary (Backend)

total_inventory_value
sum( item.quantity_on_hand × item.unit_cost )
low_stock_items
count( item.quantity_on_hand ≤ item.reorder_point )
pending_orders
count( status in ["Processing", "Backordered"] )
